# EMS implementation research

- ISA-95 separates enterprises, sites, areas, work centers, and work units. EMS uses the same distinction for operational structure and adds buildings, floors, occurrences, and terminal placement for engineering authoring. [OPC Foundation ISA-95](https://reference.opcfoundation.org/specs/OPC-10030/7.4.1)
- Factory layout tools support placing equipment in a dimensional spatial scene and evaluating layouts. EMS implements constrained desktop/web authoring, linked 2D projections, and explicit design accuracy. [Siemens factory and line design](https://www.siemens.com/en-us/products/tecnomatix/factory-line-design/)
- The glTF format standard describes right-handed, Y-up geometry in meters. EMS accepts a declared millimeter conversion for known supplier exceptions and preserves the uploaded bytes and conversion record. The Three.js controls attach to renderer objects while the versioned model retains authoritative transforms. [Khronos glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) · [Three.js TransformControls](https://threejs.org/docs/pages/TransformControls.html)
- Three.js 0.187.0 is pinned. Its imperative scene layer avoids a React renderer peer-dependency requirement and loads behind the layout component. The Node build, browser and geometry tests check compatibility with the repo's React 19 version. [Three.js documentation](https://threejs.org/docs/)
- Versioned industrial applications pin the definition consumed by operators. EMS uses one validated definition for Studio and the edge runtime, tracks dependency revisions, and pins installation and run state separately. [Tulip app versioning](https://support.tulip.co/docs/create-and-manage-app-versions) · [Tulip triggers](https://support.tulip.co/docs/triggers)
- Device rollouts require target identity, package verification, failure recovery, and observed installation evidence. EMS signs separate release, deployment, activation, and readback envelopes and keeps health evidence distinct. [AWS IoT Greengrass deployments](https://docs.aws.amazon.com/greengrass/v2/developerguide/manage-deployments.html) · [Mender artifact verification](https://docs.mender.io/artifact-creation/sign-and-verify)
- EMS uses a confidential Authorization Code client with SHA-256 PKCE, nonce, and distinct human-token audiences. The site decision endpoint is verified on each operation. [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html) · [AMS discovery](https://ams.manuqube.com/.well-known/openid-configuration)
- Native Compose uses pinned image inputs and a migration job. Cloud Supabase remains the historical sandbox environment. [Supabase self-hosting](https://supabase.com/docs/guides/self-hosting/docker) · [Docker production Compose](https://docs.docker.com/compose/how-tos/production/)

The design choices, boundary assumptions, and verification scenarios are in [ADR 0001](adr/0001-native-factory-runtime.md).

Demand-based frame scheduling and reusable geometry keep the spatial renderer idle between changes. Device certificates, rollback hooks, and durable evidence transfer inform the edge design and future enrollment integration. [React Three Fiber performance guide](https://r3f.docs.pmnd.rs/advanced/scaling-performance) · [AWS device identity](https://docs.aws.amazon.com/greengrass/v2/developerguide/device-auth.html) · [Mender state scripts](https://docs.mender.io/artifact-creation/state-scripts) · [Ignition store-and-forward](https://docs.inductiveautomation.com/docs/8.1/platform/database-connections/store-and-forward/configuring-store-and-forward)
